# 이해 확인: 기준 → 실제 시도 → 필요한 지원 → 재확인

이 문서는 질문과 이해를 돕는 보완이다. 대화 정리·개념 지도만 요청한 학습자에게 평가를 강요하지 않는다. 자신감보다 실제 답안을 사용하되, 매 턴을 시험으로 만들지 않는다.

## 1. 답을 보기 전 성공 기준

학습 목표를 관찰 가능한 행동 2~3개로 바꾼다. 예: 핵심 원리 설명, 필요한 성립 조건 구분, 다른 상황에서 적용. 질문을 제시할 때 기준도 짧게 알려 주고 시도 기록에 남긴다. 이미 받은 답안을 검토한다면 그 답을 보기 전 기준이 없었다는 사실을 기록하고 정의·사용자 목표로 기준을 재구성한다. 사후 기준을 사전 기준으로 가장하지 않는다.

동일 과제에서 학습자에게 제시한 기준은 그대로 보존한다. 판정 때 기준을 추가·변경한다면 변경 시점과 이유를 별도로 적고 사전 기준이라고 쓰지 않는다. 이번 과제에 요구하지 않은 새 적용이나 미응답 과제를 실패로 채점하지 않는다. 예: Q3에서 판정·근거 두 기준만 제시했다면, 이후의 별도 Q4 적용을 Q3의 세 번째 사전 기준이나 실패로 추가하지 않는다. 저장 전에 기준과 시점을 해당 턴의 실제 질문과 대조한다.

기준은 분야에 맞춘다. 수학은 정의·조건·계산 근거, 코드는 실제 요구 동작·경계 사례, 글은 목적·논리·근거를 본다. 판정은 각 기준의 **충족 / 미충족 / 미확정**과 실제 답안의 문장·계산·실행 근거를 연결한다. 말투·길이·AI와 같은 표현인지 여부를 점수로 사용하지 않는다.

새 적용 과제는 표현, 상황, 제약 또는 필요한 판단 중 하나가 실제로 달라야 한다. 이미 본 풀이의 숫자만 바꾸거나 공개한 답을 다시 말하게 하는 것은 충분한 독립 적용 증거가 아니다. 원리 설명이 맞아도 적용 답안이 없으면 두 증거를 모두 확보했다고 기록하지 않는다.

## 2. 지원 수준과 공개 경계

지원은 해당 과제마다 누적 기록한다. 다른 과제를 시작해도 같은 과제의 과거 힌트나 답 공개가 사라지지 않는다.

| 수준 | 제공할 내용 | 다음 행동 |
|---|---|---|
| 0 | 문제와 성공 기준. 풀이 단서 없음 | 실제 시도 대기 |
| 1 | 다시 살필 조건·빠진 관점 하나 | 시도 대기 |
| 2 | 사용할 정의·원리 하나 | 시도 대기 |
| 3 | 풀이의 첫 단계 | 시도 대기 |

완성 해설은 별도 `정답 노출: 있음`으로 기록한다. 사용자가 해설을 요청하면 제공할 수 있지만 그 과제의 후속 성공을 독립 수행으로 판정하지 않는다. 자동으로 여러 힌트를 한 번에 주지 않는다. 막혔다는 응답이나 추가 힌트 요청 후 한 단계씩 올린다.

**최소 힌트 요청은 수준 1이다.** 응답과 같은 턴에 쓴 모든 학습자용 파일에 다시 살필 조건만 넣는다. 정의를 요청받았다면 정의 자체는 설명할 수 있으나 미응답 문제에 대입해 결론을 이끌어내지 않는다. 반례가 존재함을 입증하는 핵심 성질·구성 절차도 답의 일부다. 숫자를 숨겼다는 이유로 이를 힌트라고 부르지 않는다.

파일을 쓰기 전 현재 미응답 과제를 명시하고, 각 설명이 그 과제의 결론·핵심 논증을 대신하는지 검토한다. 대신한다면 그 설명을 열린 질문으로 바꾼다. 예컨대 영벡터 문제에서는 영벡터로 비자명한 계수 조합을 만들 수 있다는 설명 자체가 핵심 해설이다. 이를 최소 힌트 노트에 넣지 않는다.

독립 시도는 **지원 수준 0, 정답 노출 없음**인 새 과제의 실제 답안이다. 힌트 뒤 정확한 답은 지원받은 성공이며 도움이 됐다는 증거로 남긴다. 도움을 지우거나 독립 성공으로 바꾸지 않는다. 잠재적인 답 누설을 발견하면 노출을 기록하고 다른 상황의 새 과제로 다시 확인한다.

## 3. 오류 원인에 맞는 개입

| 관찰한 오류 | 다음 개입 |
|---|---|
| 용어·선수 개념을 모름 | 필요한 기초 하나만 짧게 보충하고 원래 질문으로 돌아감 |
| 정의는 알지만 조건을 일반화함 | 빠진 조건을 살피게 하고 경계 사례를 비교함. 수준 1에서는 비교의 결론을 먼저 말하지 않음 |
| 원리는 맞지만 계산·실행이 틀림 | 처음 어긋난 단계만 점검. 전체 개념을 다시 강의하지 않음 |
| 외운 문장만 반복하고 이유를 설명 못함 | 표현을 바꾸거나 관계를 자기 말로 설명하게 함 |
| 배운 예시만 적용함 | 상황·제약을 바꾼 과제 하나 제시 |
| 원인을 아직 구분 못함 | 원인을 가르는 질문 하나. 오류 종류를 추정 사실로 기록하지 않음 |

정답인 부분은 보존하고 정확히 어떤 기준이 남았는지 말한다. 다른 접근이나 동등한 표현은 기준을 만족하면 인정한다. 근거 자료가 충돌하면 오류를 학습자 탓으로 돌리기 전에 자료의 정의·버전·적용 범위를 확인한다.

피드백 전에 **문제에서 주어진 조건 / 학습자가 실제로 주장한 결론 / 그 결론의 근거**를 분리한다. 인용 가능한 발언에 대해서만 오류를 지적한다. 문제에 이미 주어진 값이 학습자가 추론해 낸 결과인 것처럼 다루지 않는다. 예: `u=(0,0)`이 주어지고 학습자가 “내적이 0이라서 독립”이라고 말했다면, 검토할 것은 내적에서 독립으로의 일반화이지 내적에서 `u=(0,0)`을 도출했다는 가상의 주장이다. 원인이 불명확하면 미확정이라고 기록하고 원인을 가르는 질문을 사용한다.

다음 개입이 새 적용이면 아래 필드를 채워 **이번 응답과 기록에 같은 과제**를 남긴다. `미응답`은 이미 질문을 제시했으나 답이 없다는 뜻이다. “다음에 새로운 문제를 고르겠다”는 계획으로 대신하지 않는다. 실제 질문은 학습자가 추가 질문 없이 바로 시도할 수 있어야 한다. 그 답을 학습자 대신 만들지 않는다.

- 과제 ID: 이전 과제와 구분되는 ID.
- 주어진 조건: 실제 수치·상황·입력·제약.
- 질문: 지금 풀거나 설명할 구체적인 요청.
- 성공 기준: 해당 과제의 관찰 가능한 기준.
- 지원 및 상태: 지원 0, 정답 노출 없음, 답안 대기.

## 4. 개념 상태와 증거

| 상태 | 판정 |
|---|---|
| `unassessed` | 수행 증거가 아직 없음. 자료만 정리한 경우도 여기에 해당 |
| `learning` | 설명·연습·지원받은 성공이 있고, 독립 적용 또는 원리 설명이 아직 부족함 |
| `review-needed` | 실제 답안에서 중요한 오개념·독립 적용 실패·유지 확인 실패가 남음 |
| `verified` | 원리 재설명과 다른 상황의 독립 적용이 실제 답안으로 확인됨. 목표와 관련된 미해결 중요한 오류가 없음 |

`review-needed`에서 지원받은 수정 답이 맞으면 수정 시도와 남은 검증을 기록하고 `learning`으로 갈 수 있다. 곧바로 `verified`로 올리지 않는다. 실제 실패가 새로 나오면 이전 `verified`도 `review-needed`로 바뀐다. 과거의 성공은 삭제하지 않는다.

학습 상태와 자료 신뢰도를 분리한다. 공식 자료인지, AI 생성인지, 실제 대조·검산했는지는 출처 기록이다. `verified`는 자료가 공식이라는 뜻이 아니다. 핵심 정의가 미확정이라 답의 정확성을 판단할 수 없다면 기준 판정을 미확정으로 남기며, 해당 목표를 `verified`로 승격하지 않는다. 요청받았다는 이유로 모르는 내용을 확정하거나 인용을 만들지 않는다.

기존 세션에 `verified`만 있고 근거·지원 수준이 없으면 과거 상태를 보존하되 현재 판정은 미확정이라고 밝히고 독립 재확인을 제안한다. 옛 기록에 없던 성공 기준·지원 수준·답안을 소급해서 만들지 않는다.

## 5. 현재 이해와 유지 확인

`verified`는 현재 확보한 이해 증거다. 장기 기억 확인과 과목 전체 완료는 별개다. 개념마다 다음을 기록한다.

- 현재 이해의 근거: 원리 설명과 독립 적용의 기록 위치.
- 유지 확인: 아직 안 함 / 응답 대기 / 확인됨 / 재학습 필요, 실제 날짜와 과제 근거.
- 다음 확인: 자료 없이 설명 또는 다른 상황에 적용하는 질문, 사용자 일정에 맞는 제안 날짜·조건.

날짜가 됐거나 오래 지났다는 사실만으로 실패·통과를 만들지 않는다. 재개 첫 턴은 실제 답을 기다린다. 지연 확인에서 틀렸다면 유지 결과와 새 오류를 기록하고 그 원인만 보충한다. 힌트 뒤 고친 답은 지원받은 수정이며 유지 성공으로 덮어쓰지 않는다.

1·3·7일은 선택 가능한 초기 제안이지 필수 간격이나 영상의 규칙이 아니다. 일정이 없으면 실행 시점을 다음 세션으로 제안할 수 있다. 이때도 주어진 조건·실제 질문·성공 기준은 지금 작성한다. 시점만 미정이지 문제까지 미정으로 남기는 것은 아니다. 자동 예약·알림은 이 스킬의 기능이 아니다.

## 완료 조건

원래 목표에 맞는 도움을 제공했고, 답안·지원·판정·다음 행동이 추적 가능해야 한다. 독립 확인이 남으면 응답과 기록에 같은 구체 과제를 작성했는지 확인한다. 정리본이 풍부하거나 NotebookLM 자료가 만들어졌다는 이유로 학습을 완료하지 않는다. 실제 학습 효과와 모델 판정의 완전한 정확성을 보장하지 않는다.
